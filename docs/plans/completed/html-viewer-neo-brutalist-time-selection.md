# Neo-brutalist viewer and direct time selection

## Intent

Update the self-contained HTML report generated by `slice-render` with a
neo-brutalist visual treatment and make dragging across the timeline create a
new time range bounded by the start and end of the drag. Existing handles and
numeric inputs remain available for precise edits.

## Interfaces and architecture

- Keep profile semantics, the `.slice` format, and crate dependency direction
  unchanged.
- Limit the implementation to the generated HTML template, its embedded CSS
  and JavaScript, and the offline viewer smoke test.
- Preserve the no-network/self-contained report contract.

## Acceptance criteria

- The generated report has the neo-brutalist palette, heavy borders, and hard
  offset shadows without external assets.
- The timeline selection is visibly bounded by a high-contrast border, and the
  time-range editor is visibly bordered.
- A pointer drag anywhere in the timeline chart creates a range from the
  initial pointer position to the final pointer position, in either direction.
- Existing handle dragging, numeric time inputs, percentile controls, flame
  graph controls, and offline execution continue to work.

## Verification

- Renderer unit tests assert the new viewer contract: passed (`3` tests).
- `tests/viewer-smoke.js` now simulates a timeline drag and checks the
  resulting time inputs; execution was unavailable because Node.js is not
  installed in the environment.
- `cargo fmt --all -- --check` and `cargo test -p slice-render`: passed.
- The full `just check` gate reached policy and formatting, then was blocked by
  missing development linker libraries for `slice-ebpf` (`libelf`, `libz`, and
  `libbpf`).
